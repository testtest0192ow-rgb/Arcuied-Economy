# ARCUEID Economy + Core

## Запуск в Termux

```bash
pkg update && pkg upgrade
pkg install nodejs-lts git

git clone <твой репозиторий>
cd arcueid-economy
npm install

cp .env.example .env
# открой .env и заполни:
#   DISCORD_TOKEN, DISCORD_CLIENT_ID — из Discord Developer Portal
#   MONGODB_URI — из MongoDB Atlas
#   BOT_OWNER_ID — твой Discord ID
#   MAX_GUILDS — сколько серверов максимум (по умолчанию 10, не список ID — просто лимит)
#   TEST_GUILD_ID — необязательно, для мгновенного обновления команд во время разработки

npm run deploy-commands   # регистрирует команды глобально (может занять до ~1 часа на всех серверах;
                          # если задан TEST_GUILD_ID — там команды появятся сразу)
node src/seed-items.js <guildId>   # добавляет тестовые предметы в магазин конкретного сервера
npm start                 # запускает бота
```

## Что уже готово

**Команды:** `/balance` `/give` `/timely` `/profile` `/shop` `/buy` `/inventory`
`/use` `/sell` `/leaderboard` `/transactions` `/coinflip` `/dice` `/duel`
`/gifts` (send/list/hide) `/marry` `/rep` `/battle` `/mogcancel` `/mogstats` `/mogtop`
`/kiss` `/pat` `/cuddle` `/slap` `/highfive`
`/eco` (админ: give/remove/set/reset/balance)

27 команд. `/blackjack`, `/poke` и `/tickle` убраны по прямому запросу.

**Убрано отсюда специально:** `/avatar` `/banner` `/userinfo` `/serverinfo` `/poll` —
это Core/Utility, не Economy, будут отдельным ботом, когда до него дойдём по плану.

- **Тонкая линия-разделитель исправлена.** Раньше `DIVIDER` рисовался обычным текстом
  в полный размер — толсто, не как у референсов. Теперь использует Discord-синтаксис
  `-#` (мелкий приглушённый подтекст) — правка в одной константе (`src/utils/embeds.js`)
  чинит линию сразу во всех ~25 командах бота, которые её используют.
- **Application Emoji.** `npm run upload-app-emoji` — заливает файлы из `assets/emoji/`
  как эмодзи, принадлежащие самому боту (работают на любом сервере сразу, без привязки
  к гильдии). См. `assets/emoji/README.md`. В конце выводит готовые `<:name:id>` строки
  для вставки в код.

- `/duel` и `/dice` теперь показывают **собственную анимацию**, сгенерированную сервером
  (Canvas + `gifenc`, без внешних ассетов и без риска по копирайту) — абстрактные
  клинки/кубик в фирменных цветах, не попытка скопировать чужой рисованный стиль.
  Генерируется один раз и кэшируется в памяти процесса (контент одинаковый для всех
  дуэлей/бросков, пересчитывать на каждый вызов незачем).
  Если в `.env` всё же заданы свои ссылки (`DUEL_GIF_URL`/`DICE_GIF_URL`) — они имеют
  приоритет над сгенерированной анимацией.
  **Не проверено живым запуском** (в этой среде разработки нет доступа к npm-реестру,
  чтобы физически поставить `@napi-rs/canvas`/`gifenc` и прогнать код) — логика
  перепроверена вручную дважды, но финальная проверка на реальном сервере за тобой.

**`/kiss` `/pat` `/cuddle` `/slap` `/highfive`** — каждый вызов подтягивает свежую
случайную аниме-гифку с nekos.best (бесплатный публичный API именно для такого —
не нужен токен, не нужно ничего хостить самому). Если API недоступен — команда
всё равно отработает, просто без картинки, не упадёт.

**Сервисы:**
- `TransactionService` — единственное место, где меняется баланс. Атомарные операции,
  идемпотентность, защита от гонок через Mongo session transaction.
- `ItemService` — покупка/продажа/использование предметов, атомарно (Mongo-транзакция
  сразу по кошельку и инвентарю).
- `GiftService` — отправка/открытие подарков (монеты и предметы), эскроу на отправке.
- `DuelService` — вызов/принятие/отклонение/отмена, эскроу обеих ставок в одной
  Mongo-транзакции, провably-fair определение победителя, статистика побед/поражений.
- `BlackjackService` — полноценная раздача карт (детерминированная перетасовка колоды
  через `GameFairnessService`), Hit/Stand/Double, устойчив к двойному клику (курсор
  колоды проверяется атомарно).
- `GameFairnessService` — provably-fair результаты (HMAC-SHA256 от serverSeed+
  clientSeed+nonce), никакого голого `Math.random()`. Используется в `/coinflip`,
  `/duel`, `/blackjack`.
- `PermissionService` — MVP-проверка прав для `/eco` (bot owner или Discord
  Administrator); полноценная Member/Moderator/Admin/Owner/BotOwner система придёт
  вместе с Core/Moderation ботами.

**UX-детали:**
- `/balance` эфемерный по умолчанию, с кнопкой «Показать всем».
- `/timely` со стрик-бонусом, баланс сразу в ответе.
- `/shop` и `/leaderboard` — через select-меню по категориям, не простыня текста.
  `/shop` дополнительно — сортировка (Популярные/Дешёвые/Дорогие/Новые), популярность
  считается по `timesPurchased` (растёт при каждой покупке).
- `/buy`, `/use`, `/sell` — автокомплит по ключу предмета/инвентарю.
- `/sell`, `/eco` — требуют подтверждения (опасные операции).
- `/duel` — публичное сообщение с Принять/Отклонить/Отменить, таймаут 60 сек,
  автоотмена без списания монет, если никто не отреагировал.
- `/blackjack` — состояние игры сохраняется в БД (переживает рестарт бота).
- `/profile` — теперь настоящая Canvas-карточка (PNG, генерируется на лету):
  аватар с кольцом-акцентом, ник, валюты крупно, чипы статистики (репутация,
  дуэли, серия /timely), пометка "💍 в браке с..." если применимо. Если рендер
  по любой причине не удался (например, не хватает шрифта) — падает назад на
  обычный текстовый эмбед, не роняет команду.
  **Важно:** нужен шрифт с кириллицей в `assets/fonts/` — см.
  `assets/fonts/README.md`, иначе текст на карточке может выглядеть криво.
- `/give` теперь удерживает комиссию (`GIVE_FEE_PERCENT` в `.env`, по умолчанию 2%) —
  получатель видит сумму за вычетом комиссии, отправитель видит её заранее в
  подтверждении. Комиссия просто уходит из экономики, никому не начисляется.
- Магазин ролей — предметы с `category: 'role'` в `/buy` выдают настоящую
  Discord-роль (создаётся автоматически при первой покупке через
  `RoleAutomationService`, дальше переиспользуется, без дублей). Если у бота
  не хватает прав "Управление ролями" — деньги всё равно списаны (это
  известное ограничение, без компенсирующего возврата пока), но пользователь
  явно предупреждается в ответе.
- Бот работает на любых серверах, куда его добавишь, но сам выходит с любого сервера сверх лимита `MAX_GUILDS` (по умолчанию 10) — никакого заранее заданного списка ID не нужно.
- Ошибки никогда не показываются пользователю напрямую.
- `/dice` — угадать грань кубика (1-6), выплата ×5 при угадывании, provably fair.
- `/marry` — предложение через кнопки (Принять/Отклонить, 60 сек), защита от двойного
  брака (перепроверка перед подтверждением), `/marry divorce` для развода.
- `/profile` показывает кнопку «Любовный профиль», только если пользователь в браке.
- `/battle` — вызов на Mog Battle через кнопки (Принять/Отклонить/Отменить, 60 сек),
  сравнение на реальных Discord-метриках (возраст аккаунта, время на сервере, роли,
  буст, свой аватар) с понятными единицами, не "магические баллы из 10".
  `/mogcancel` отменяет свой ожидающий вызов, `/mogstats`/`/mogtop` — статистика.

сможет. Нужно либо загрузить те же картинки как emoji на твой сервер-заготовку

добавить их как application emoji своему боту.

## Про "Unknown interaction" (DiscordAPIError 10062)

Если видишь эту ошибку в логах — это почти всегда **не баг кода**, а сеть: Discord даёт
всего 3 секунды на подтверждение команды (`deferReply`), и если запрос физически не
успевает дойти до Discord за это время (слабый сигнал, VPN добавляет задержку) —
токен считается истёкшим. Проверено: обработчики событий регистрируются ровно один
раз (`grep client.on/once` в `index.js` подтверждает), дублирования в коде нет.
Если это происходит стабильно — попробуй отключить VPN или проверить на Wi-Fi;
если пропадает — дело было в скорости соединения, а не в боте.

## Проверено (4 прохода по коду)

- Синтаксис всех файлов — `node --check` проходил после каждой партии команд, включая
  финальную (`/duel /blackjack /gifts /eco`) — без ошибок.
- Race conditions: `/give`, `/buy`, `/sell`, `/duel` (обе ставки), `/blackjack`
  (Hit/Double) — везде атомарное условие в фильтре запроса (баланс/количество/курсор
  колоды), не read-then-write.
- Идемпотентность: денежные операции везде помечены уникальным `idempotencyKey`.
- Двойной клик: кнопки убираются/деактивируются сразу после первого клика везде,
  где идёт подтверждение; `/blackjack` дополнительно защищён атомарным условием на
  курсор колоды — повторный Hit просто не найдёт документ для обновления.
- Нашёл и исправил баг при ревью: в `/blackjack` ничья (push) ошибочно писалась
  в историю транзакций как проигрыш — исправлено на отдельный тип `game_push`.
- `/eco` скрыта по умолчанию (`setDefaultMemberPermissions(0)`) и дополнительно
  проверяется на сервере через `PermissionService`, а не только по видимости команды.

Не проверено вживую (нужен реальный Discord-токен, MongoDB и минимум один сервер —
этого у меня в песочнице нет): фактический деплой команд, поведение Mongo Atlas
session transactions на твоём кластере, поведение автокомплита/select-меню/долгих
дуэлей и блэкджек-сессий в реальном клиенте Discord.

Первое, что стоит сделать после `npm start`: пройтись по каждой команде вручную,
специально попробовать дважды кликнуть на всех подтверждениях и кнопках игр
(`/give`, `/sell`, `/coinflip`, `/duel`, `/blackjack`, `/eco`), и посмотреть логи
в консоли — если где-то тихо проглочена ошибка, она будет видна там.
